# Release 0.2.0

Status: **blocked on repository secrets** (27 Sep 2026). #10 merged, tag `v0.2.0` pushed on
its merge commit `884ddfe`; the release run stopped at `publish` because the crates.io token
is rejected. Nothing was published. Install docs reverted until the release completes.

## Context

`main` has carried version 0.2.0 in `Cargo.toml` since remote mode merged (#6), but
crates.io, the GitHub releases page and `install.sh` still served 0.1.0, so the README had
to tell people to build from git for remote mode. The owner asked for the 0.2.0 release:
tag, GitHub release, the five crates on crates.io, and the Homebrew formula in
`omar16100/homebrew-tap`.

Problems found in the release pipeline before tagging:

- `release.yml` ran `cargo publish ... || echo "already published"` for every crate, so an
  auth, version or packaging failure was reported as success and the job went green.
- `update-homebrew.yml` listened for `release: published`, but the release is created by
  `release.yml` with `GITHUB_TOKEN`, and events caused by `GITHUB_TOKEN` do not start other
  workflows. The formula update would never have run.
- The sha256 step wrote `$(shasum ...)` straight into the output, so a missing archive
  gave an empty checksum instead of a failure.
- `install.sh` looks for `checksums.sha256` on the release, and no release had one.
- Crates had no `readme`, `keywords`, `categories` or license files in their packages.
- `Cargo.lock` pinned `chacha20 0.10.1`, which is yanked (not in the build graph for any
  target; cargo warned about it while packaging).

## Approach

`release.yml` (tag `v*`):

1. `verify`: the tag must be `vX.Y.Z` and equal the workspace version, `CHANGELOG.md` must
   have a `## [X.Y.Z]` section, and `cargo package --workspace --locked` must package and
   build every crate against the others' packaged sources.
2. `binaries`: the three targets `install.sh` and the formula use, built with `--locked`;
   native builds must print `parsnip X.Y.Z`, the cross-built x86_64 macOS binary gets an
   arch check.
3. `publish`: crates in dependency order. A version already in the crates.io sparse index
   is skipped; "already exists" from cargo is accepted only when the index agrees; a
   dependency not yet in the index is retried with a growing wait; anything else fails.
4. `release`: binaries plus `checksums.sha256`, notes taken from the CHANGELOG section.
5. `homebrew`: calls `update-homebrew.yml` directly.

`update-homebrew.yml` also runs on `workflow_dispatch` (dry run by default: prints the
formula and runs `git push --dry-run` against the tap to prove the token can push) and
still on `release: published` for a release made by hand. It checks `checksums.sha256`,
checks each archive has a top-level `parsnip`, runs the Linux binary, and fails on any
missing or malformed checksum. The formula test asserts `parsnip --version` prints the
formula version.

Docs are written to be true once the tag's workflows finish: README, `docs/llms.txt`,
`docs/todo.md` and `docs/spec.md` say `cargo install parsnip-cli` installs 0.2.0 with
remote mode. Homebrew is documented only after the formula is live and checked, in a
follow-up change.

## Phases

1. Preflight on a fresh clone of `main`: `cargo publish --dry-run -p parsnip-core` passes;
   the four dependents fail on their own because `parsnip-core 0.2.0` is not in the index
   yet, and `cargo publish --workspace --dry-run --locked` packages and verifies all five
   through a local overlay registry. Secrets `CARGO_REGISTRY_TOKEN` and
   `HOMEBREW_TAP_TOKEN` exist.
2. Release PR: workflows, crate metadata, lockfile, `CHANGELOG.md`, docs. External review.
3. After merge: dry-run `update-homebrew.yml` against v0.1.0 to prove the tap token.
4. Tag the merge commit, push the tag, watch `release.yml`.
5. Verify: crates.io max version, `cargo install parsnip-cli --version 0.2.0` in a
   throwaway root, release assets, formula sha256 against the downloaded archives,
   `brew audit` and `brew fetch` without installing.
6. Follow-up docs: Homebrew install line once the formula is verified.

## Verification

- `actionlint` on all workflows.
- The formula template, generated from the v0.1.0 archives, passes `brew style`.
- The CHANGELOG extraction prints the 0.2.0 section, and fails for a version with no
  section.
- The sparse index check reports 0.1.0 as present and 0.2.0 as absent for `parsnip-core`
  and `parsnip-cli`.

## Recovery

The tag is correct and stays: the failure is credentials only. After the secrets are
replaced, optionally prove the tap token first with
`gh workflow run update-homebrew.yml -f tag=v0.1.0 -f dry_run=true`, then
`gh run rerun 36302226017 --failed` (GitHub allows re-runs for 30 days after the run). If
that window has passed or the tag has to move, delete the remote tag,
re-tag the intended commit, and push it again; `publish` skips versions already on
crates.io either way.
